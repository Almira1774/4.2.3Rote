Архитектура маршрутизации, деплой и инфраструктура проекта

В ходе рефакторинга проект был переведен с классического управления состоянием (Redux) на современный Data-роутинг React Router v7 с использованием асинхронных лоадеров (loaders) [строка 3]. Это позволило сделать URL единственным источником правды для фильтрации, пагинации и детального просмотра вакансий [строка 1].
При деплое Single Page Application (SPA) на статический хостинг GitHub Pages был решен ряд важных инфраструктурных и технических задач [строка 3]:

1. Кроссплатформенный скрипт генерации 404.html (Устранение ошибок при F5)При перезагрузке страницы (F5) на внутренних путях (например, /vacancies/moscow) сервер GitHub Pages ищет физический файл moscow.html и возвращает ошибку 404 [строка 3, строка 5]. Чтобы сохранить красивые и SEO-дружественные URL без использования хэшей (/#/), было внедрено дублирование базового файла [строка 5].
Проблема: Традиционные Windows-команды копирования (вроде xcopy) намертво ломают автоматическую сборку в GitHub Actions, так как виртуальные машины GitHub работают на Linux (Ubuntu) [строка 3].
Решение: В package.json в скрипт build была добавлена универсальная, кроссплатформенная команда на базе Node.js, которая работает одинаково стабильно на любой ОС:
"build": "tsc && vite build && node -e \"require('fs').copyFileSync('dist/index.html', 'dist/404.html')\""

При каждой сборке автоматически создается копия index.html под именем 404.html [строка 3]. Теперь при перезагрузке хостинг отдает этот файл, а внутренний роутер React Router v7 корректно подхватывает путь и запускает лоадер [строка 5].

2. Фиксированный базовый путь в конфиге ViteЧтобы при сборке все скомпилированные скрипты, CSS-стили и шрифты из папки dist/assets получили правильный префикс и успешно загружались сервером, в файле vite.config.ts был жестко зафиксирован базовый путь, соответствующий названию репозитория:typescript

export default defineConfig({
  plugins: [react()],
  base: '/4.2.3Rote/', // Четкое указание папки репозитория на GitHub Pages
})

Это полностью исключило ошибку «MIME type / Failed to load resource», когда браузер при перезагрузке пытался искать стили от корня домена, а не внутри папки проекта.

3. Автоматизация деплоя через GitHub Actions (CI/CD)Был полностью ликвидирован нестабильный и устаревший ручной деплой через локальный терминал компьютера [строка 3].
Решение: В корень проекта была добавлена служебная папка .github/workflows с конфигурационным файлом deploy.yml.
Как это работает: Теперь при каждом обычном git push origin main удаленный сервер GitHub самостоятельно инициализирует чистое окружение на Node.js 20, проводит строгую компиляцию TypeScript, собирает проект с помощью настроенного нами Node-скрипта и мгновенно публикует готовую папку dist на хостинг [строка 3]. Это полностью исключило ошибки авторизации и конфликты веток на локальной машине разработчика.
